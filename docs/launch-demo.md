# ローンチ用デモ動画の撮影手順

30〜60秒の無音デモ（画面録画）を1本撮るための手順です。動画ファイルはこのリポジトリには含めません。README に埋め込むスクリーンショット2枚の撮影手順は、末尾の[スクリーンショットの撮り直し](#スクリーンショットの撮り直し)にあります。

## この動画で伝えること

**人間は重要な判断だけを行い、その他の作業は AI のチームが進めている。**

「AI がたくさん動いている」ことを見せる動画ではありません。視聴者に残す印象は次の1点です。

> 人間の操作は「気づきを1行書く」「進めるを押す」「受け入れて完了を押す」の3回だけ。その間の調査・実装・レビューは AI が worktree / branch / PR 単位で進めている。

## 撮影前の準備

1. **実データではなくデモ用のプロジェクトを使う**。`board.yaml` にはカードの本文、`evidence`、ブランチ名、PR URL が表示されます。公開できない内容が映らないこと。
2. ホームディレクトリの実名が画面に出るのは次の3か所です。デモ用アカウントか、映って問題ないパスで撮ります。
   - トップバーの board のパス表示（`boardPath` をそのまま表示します）
   - カードモーダルの「担当セッション」欄。セッション名の下に worktree のパス（`changes[].agent.cwd`）が出ます
   - サイドバーの「司令塔を新しく起動」を押したときに出るディレクトリ入力欄。対象プロジェクトのパスが初期値として入っています

   サイドバー上部の司令塔の表示は「ワークスペース名 / サーフェス名」で、パスは含みません。
3. 事前に board を次の状態にしておきます。あとの各カットで「その状態のカード」が必要になるためです。
   - `受信箱` に0〜1件
   - `実装中` に1件。`changes` に2件。1件は PR がマージ済みで change の状態が `done`、もう1件は PR を作成済みで状態は `確認中`（`change pr` は open の PR に対して change を `確認中` にします）。カードのタグは `done/total` なので、この状態で `変更 1/2` と表示されます
   - `完成確認待ち` に1件。`review` フィールドに独立レビューの結果、`acceptance_conditions` に完成の条件が入っている
   - `decisions_required` に1件（「今日の判断」バーを出すため）
4. cmux を起動し、司令塔セッションを登録済みにしておきます（サイドバー上部に司令塔のセッション名が出ている状態）。トップバーのバッジが `cmux 接続済み` であることを確認します。
5. ブラウザは 1440x828 程度（同梱のスクリーンショットと同じ比率）。ブックマークバーと拡張機能のアイコンは隠します。
6. サイドバーは初回起動時は開いています。カット1は閉じた状態から始めるため、録画前に **⌘B** で閉じておきます。
7. 録画は 30fps 以上、カーソルの動きはゆっくり。クリックの瞬間が分かるようにします。

## カット割り（合計 55 秒）

### カット1 — 全体像（0:00–0:05 / 5秒）

- 画面: ボード全体。右サイドバーは**閉じた**状態から開始します。
- 操作: なし。カーソルを止めておきます。
- 見せる場所: 上部の黄色い「今日の判断」バー（最大3件）、水色枠のカード（あなたの操作待ち）、黄色枠のカード（AI が作業中）。
- 字幕案: `You are the Overlord. You make the decisions that matter.`

### カット2 — 気づきを1行入れる（0:05–0:13 / 8秒）

- 操作: トップバーの **「気づきを追加」** をクリック → ダイアログの **「1行の見出し」** に1行だけ入力 → **「追加」** をクリック。
- 画面の変化: ダイアログが閉じ、`受信箱` 列の**先頭**に新しいカード（ID は `OV-NNN`）が追加され、**そのカードのモーダルが自動で開きます**。
- 補足: 「プロジェクト（任意）」「根拠・再現手順（任意・複数行可）」は空のままにします。入力欄を1つしか使わないことが、この動画の主張の一部です。プロジェクト欄が空のときの ID 接頭辞は既定の `OV` になります（入力した場合は、英数字以外を取り除いた先頭4文字を大文字にしたものが接頭辞になります）。
- 字幕案: `気づきを1行書く。それだけでカードになる。`

### カット3 — 「進める」を1回押す（0:13–0:21 / 8秒）

- 画面: カット2で自動的に開いたカードのモーダル。
- 操作: 「司令塔への指示」の **「進める」** を1回クリック。
- 画面の変化: 画面下部中央に `送信しました` のトーストが出ます。モーダルは開いたままです。
- 見せる場所: 指示ボタンが `状況を聞く / 進める / 実装ブリーフ / 独立レビュー / 完了の可否` の5つであること。人間が打つコマンドは存在しないこと。
- 字幕案: `人間の操作はここまで。`

### カット4 — AI チームが動き出す（0:21–0:31 / 10秒）

- 操作: **⌘B**（またはトップバーのサイドバーアイコン）でサイドバーを開く。モーダルは Escape または枠外クリックで閉じます。
- 画面の変化: 右サイドバーに司令塔の端末ミラーが出ます。カット3の指示は押した時点で送信済みなので、ここでは司令塔がその指示に応答している途中が映ります。司令塔はサブエージェントを起動します。
- 見せる場所: 会話相手が司令塔1つだけであること。各カードの作業はそこから割り振られること。
- 注意: サイドバーが自動で開くことはありません。開くのは必ず操作した結果です。
- 字幕案: `司令塔が受け取り、担当のサブエージェントに割り振る。`

### カット5 — worktree / branch / PR 単位で進む（0:31–0:41 / 10秒）

- 操作: `実装中` 列のカード（黄色枠、`変更 1/2` のタグ付き）をクリックして開く。
- 見せる場所（モーダル内、上から順にスクロール）:
  - **担当セッション（`<変更ID>`）** — 割り当てられた cmux セッションと worktree のパス。右に **「cmux で開く」** ボタン
  - **変更（PR単位）** — 変更ごとに ID / 状態ラベル / タイトル / ブランチ名 / `PR #n`（リンク）/ PR の状態
- 補足: この欄は読み取り専用です。変更は人間の意思決定単位ではないため、編集できません。
- 字幕案: `1変更 = 1 worktree = 1 branch = 1 PR = 1 エージェント実行。`

### カット6 — 実装した AI とは別の AI が確認する（0:41–0:48 / 7秒）

- 操作: `完成確認待ち` 列の水色枠のカードを開く。
- 見せる場所: **「完成の条件」** 欄と、その下にある **「確認結果」** 欄（独立レビューの結果）。モーダル内の並び順は「完成の条件」が上、「確認結果」が下です。
- 補足: レビューは実装したサブエージェントとは別のサブエージェントが実行します。レビュー済みの commit が PR の先頭と食い違うときは `sync` が警告を出します。その変更をこの列に上げないことは、スキルの規則として定めています。
- 字幕案: `実装した AI に、自分の変更を承認させない。`

### カット7 — 人間が受け入れる（0:48–0:55 / 7秒）

- 操作: 同じモーダル右上の **「受け入れて完了」** を1クリック。
- 画面の変化: `<カードID> を完了にしました` のトーストが出て、モーダルが閉じ、カードが `完了` 列へ移動します。担当・次にすること・止まっている理由はクリアされます。
- 最後の1〜2秒: ボード全体に引く。
- 字幕案: `You make the decisions that matter.`

## 撮影後のチェック

- [ ] 人間のクリックが「気づきを追加 → 追加 → 進める → 受け入れて完了」の4回だけに見えるか
- [ ] 実在しない画面・ボタン・状態遷移が1つも映っていないか
- [ ] ホームディレクトリの実名、社内プロジェクト名、実在の PR URL が読み取れないか
- [ ] 55秒以内に収まっているか（超えたらカット4とカット5を各2秒詰める）
- [ ] 音声なしで意味が通るか（SNS の自動再生はミュート）

## 書き出し

- SNS 用: MP4 / H.264 / 1920x1080 または元解像度そのまま / 8Mbps 程度
- README へ埋め込む場合は GIF ではなく、GitHub にドラッグ&ドロップした MP4 を使います（GIF はファイルサイズと文字の可読性で不利です）

## スクリーンショットの撮り直し

README に埋め込んでいる `docs/images/console-board.jpg` と `docs/images/card-modal.jpg` を、架空のデモ用ボードで撮り直すための手順です。

### なぜ撮り直すか

現在同梱されている2枚には、次の情報が読み取れる大きさで写っています。

`docs/images/console-board.jpg`（1456x828 / JPEG / 約 114KB）

- トップバーの board パス表示: `/private/tmp/claude-501/-Users-kunimasa-dev-…`（ホームディレクトリ名 `kunimasa` を含む）
- カード `WD-015` / `WD-014` とプロジェクト名 `WhiteDB`、カード `RC-UX-001` / `RC-UX-002` とプロジェクト名 `RaidCoder`、およびそれぞれのタイトルと「次にすること」
- 「今日の判断」バーの本文（`RC-UX-001（ログイン後に元のURLへ戻る）の実装ブリーフを承認し、実装を開始してよいか`）
- 司令塔サイドバーの端末ミラーのプロンプト行: `/private/tm/claude-5/-Users-kunimasa-dev-o/c/scratchpad`

`docs/images/card-modal.jpg`（1456x828 / JPEG / 約 100KB）

- カードモーダルの `RC-UX-003 · RaidCoder`「検索結果の並び順が呼び出し毎に変わる」と、その「次にすること」「困っていることと根拠」「完成の条件」
- 背景に見えているボードのカード（`WD-015` / `WD-014`）、トップバーのパス、司令塔サイドバーのパス

`WhiteDB` と `RaidCoder` は実在しうるプロダクト名で、パスにはホームディレクトリのユーザー名が含まれます。リポジトリは公開されており、README から誰でも読める状態です。そのため、実在しない題材だけで構成した `docs/product-ops/board.example.yaml` で撮り直します。

### 撮影用のボードを起動する

リポジトリのルートで実行します。

```bash
rm -rf /tmp/overlord-demo
mkdir -p /tmp/overlord-demo/docs/product-ops
cp docs/product-ops/board.example.yaml /tmp/overlord-demo/docs/product-ops/board.yaml
./scripts/console.sh /tmp/overlord-demo --port 7396
```

起動すると次が表示されます。ブラウザで `http://127.0.0.1:7396` を開きます。

```text
Overlord Console  http://127.0.0.1:7396
board             /tmp/overlord-demo/docs/product-ops/board.yaml
```

トップバーに出るパスは `/tmp/overlord-demo/docs/product-ops/board.yaml` で、ホームディレクトリ名を含みません。ポート 7396 が使われている場合は、空いている別のポートに変えます。

`board.example.yaml` はカード8枚を持ち、カンバンの8列すべてに1枚ずつ入ります。カード枠の色は次のとおりです（実測値）。

| 枠の色 | カード | そうなる条件 |
| --- | --- | --- |
| 水色（あなたの判断待ち） | `NOTE-009`, `BILL-008` | `state` が `acceptance`、または `owner` が `user`、または `decisions_required` がその ID を参照している（完了・停止中は除く） |
| 黄色（AI が作業中） | `BILL-021`, `BILL-013`, `NOTE-022` | `owner` が `claude` で、状態が完了・停止中以外（水色の条件を満たす場合は水色が優先される） |
| 色なし | `NOTE-014`, `NOTE-003`, `BILL-005` | 上のどちらにも当てはまらない |

`board.example.yaml` は `changes`（PR単位の変更）を3枚のカードに持たせてあります。`BILL-013` は `変更 1/3`、`NOTE-022` と `BILL-008` は `変更 1/2` と `変更 2/2` のタグが出ます。

### 撮影の共通設定

- ブラウザの表示領域を 1456x828 にします（既存2枚と同じ）。ブックマークバーと拡張機能のアイコンは隠します。
- 司令塔サイドバーは初回起動時は開いています。端末ミラーには、登録した cmux セッションの実際の出力とカレントディレクトリが出ます。デモ用に用意したセッションでない場合は、**⌘B** で閉じてから撮ります。
- `board.example.yaml` はどのカードにも `agent` を書いていないため、モーダルの「担当セッション」欄は `未割り当て（司令塔が起動します）` と表示されます。実際のセッション名を写したい場合は、撮影前にコンソールから cmux セッションを割り当てます。その場合、`/tmp/overlord-demo` 側の `board.yaml` に実在の cmux UUID と worktree のパスが書かれ、パスはモーダルに表示されるので、写ってよいパスか確認してください（`docs/product-ops/board.example.yaml` 自体は書き換わりません）。

### 1枚目 — ボード全景（`docs/images/console-board.jpg`）

- 写すもの: トップバー（`Overlord` のロゴ、board のパス、「気づきを追加」、`cmux 接続済み` バッジ）、黄色い「今日の判断」バー（2件）、カンバンの列と、水色枠・黄色枠・枠なしのカードが同時に見える状態。
- モーダルは閉じた状態にします。
- 写してはいけないもの: 実在のプロジェクト名、ホームディレクトリの実名を含むパス、実在の PR URL、司令塔サイドバーに映る実際の作業内容。

### 2枚目 — カードモーダル（`docs/images/card-modal.jpg`）

- 操作: `完成確認待ち` 列の `BILL-008` をクリックしてモーダルを開きます。
- 写すもの: ヘッダの `BILL-008 · Billing API` とタイトル、右上の「受け入れて完了」ボタン、「司令塔への指示」の5つのボタン、「状態」「次にすること」「担当」、および下へスクロールした「変更（PR単位）」（`overlord/BILL-008-C1` / `PR #24`（merged）など）、「完成の条件」「確認結果」。
- モーダル内は縦にスクロールできます。1枚に収まらない場合は、「変更（PR単位）」が見える位置で撮ります。カードの中身が階層になっていることが伝わる位置が優先です。
- 写してはいけないもの: 1枚目と同じ4点。背景に見えるボードのカードも架空の内容であることを確認します。

### 差し替えと後始末

- 保存先はそのまま `docs/images/console-board.jpg` と `docs/images/card-modal.jpg` です。ファイル名を変えなければ README の変更は不要です。
- 形式とサイズは既存と揃えます。JPEG、1456x828、1枚あたり 100〜120KB 程度。macOS の ⇧⌘4 は PNG を出すため、`sips -s format jpeg` などで JPEG に変換します。
- 差し替え後、README.md と README.en.md の画像が表示されることを確認します。
- 撮影が終わったらコンソールを停止し、一時ディレクトリを削除します。

```bash
# コンソールを起動した端末で Ctrl-C
rm -rf /tmp/overlord-demo
```
