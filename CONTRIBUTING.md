# Contributing

Thanks for looking at Overlord. Issues and pull requests are welcome.

## Before a large change

Open an issue first and describe the problem you hit. Overlord deliberately keeps a small surface: one board file, five skills, one console. A change that adds a second source of truth, or that moves a decision away from the human, is likely to be declined.

## Repository layout

| Path | What it is |
| --- | --- |
| `skills/` | The five agent skills. One directory per skill; `SKILL.md` frontmatter `name` must match the directory name |
| `console/src/` | The Bun server, the board reader/writer, the cmux client, and `change.ts` |
| `console/frontend/` | The React + shadcn/ui frontend source |
| `console/public/` | The built frontend. **Committed**, and regenerated by the build |
| `scripts/` | `install.sh`, `console.sh`, `change.sh` |
| `docs/product-ops/board.yaml` | This repository's own working board. **Not tracked** — it is listed in `.gitignore`, so running Overlord against this repository produces no diff |
| `docs/product-ops/board.example.yaml` | A tracked example board. It is both the starting point for a hand-written board and the demo board used for the screenshots in `docs/images` |

`board.example.yaml` is public documentation, so keep every project name, card, branch, pull request, and commit id in it invented. It must not contain a real cmux session id or a home directory path; `docs/launch-demo.md` explains how it is used for the screenshots.

## Running things locally

```bash
# server-side tests (board read/write, change.ts)
cd console && bun test

# run the console against any project directory
./scripts/console.sh /path/to/project --port 7400

# frontend: install deps once, then typecheck or rebuild
cd console/frontend && bun install
cd console && bun run typecheck
cd console && bun run build      # regenerates console/public
```

If you touch anything under `console/frontend/`, run `bun run build` and commit the regenerated `console/public` in the same pull request. A frontend change without the rebuilt bundle does not reach users.

## Pull requests

- One change per pull request; keep the diff small enough to read in one sitting.
- Add or update a test in `console/src/*.test.ts` for behavior changes on the server side.
- `README.md` (Japanese) and `README.en.md` (English) are the same document in two languages. If you change one, change the other.
- Document only behavior that exists in the code.
